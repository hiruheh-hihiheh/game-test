# Saves

- Files: `starfall_save.cfg` with a backup `starfall_save.cfg.bak`, written through a temp file so a crash cannot leave half a save.
- `Save.load_data()` starts from a clean slate, tries the main file, then the backup, and returns where the data came from: `"main"`, `"backup"` or `"none"` (fresh start). A file that parses but holds no progress is skipped in favour of the backup.
- Version 1 files (before the current format) go through `_migrate_v1`. Stars become star masks, the bosses already beaten keep their blueprints, and old settings map to the new ones.
- Every load, including a fresh start and each fallback, first resets progress (`reset_progress`), settings (`reset_settings`, a deep copy of `DEFAULT_OPT` made in place) and the map position (`reset_view`, session only). Then only the settings the file actually holds are merged in, so nothing leaks from a save loaded earlier.
- `Save.reset_progress()` returns every progress value to a new player's. Settings are untouched. The Settings reset button uses it, so new fields cannot be forgotten.
- Under `-- --test` the game uses `user://starfall_test_save_<pid>.cfg`, named after the process, so two test runs at once never delete each other's files. Files left by crashed runs are cleaned up at the next start.
- The save tests (`_test_save_loading` in `tools/test_game.gd`) cover a fresh install, a legacy v1 save loaded over leftover state, a v1 save with only a backup, a current save round trip, and backup fallback from a corrupt, empty or missing main file.
- Cloud save adds one record and one folder beside the save, written only by the cloud code and removed with the test save. `starfall_save.cfg.cloud` holds fingerprints of the last synced state, its time and a one-way hash of the Google Play Games player id (never the id or any token). **`starfall_save.cfg.recovery/`** holds recovery copies, kept before anything is replaced: `<generation>_cloud_save.blob` (a cloud save byte for byte as the cloud sent it, even if unreadable), `<generation>_local_save_file.cfg` (a copy of `starfall_save.cfg`), `<generation>_local_progress.blob` and `<generation>_google_version_N.blob` (versions Google reported in a conflict), plus a `README.txt` and an empty `<generation>.set` folder per generation. The highest generation number is the newest; files of one operation share a number. A generation is reserved by creating its `.set` folder, which only one process can do, so two processes sharing a save cannot write the same recovery file. **A recovery file is never overwritten, truncated or deleted by the game**: each is written to a temporary `tmp_*.part` file, read back and compared byte for byte, renamed into place only if that name is free, and read back again (a copy that fails is renamed `.unverified`), so a failed backup leaves every older one untouched. Do not delete anything there until you have recovered what you need; only `tmp_*.part` files are safe to delete, and the game itself removes only those left by a process that is no longer running. None of it is read to load the game. `Save.restore_progress()` is the one way a cloud save is applied: reset progress, apply validated data, write. `Save.saved` is emitted after every successful write. See [CLOUD_SAVE.md](CLOUD_SAVE.md).
